# Ream Meeting #83 Recap

## Overview

This week's call was a quick one. Topics spanned Hive and Docker build compatibility — a Grandine tag change surfacing ream image failures, plus a multi-stage Dockerfile split — long-run memory and CPU benchmarking, data-availability work on the beacon client (parent/child import ordering and Sepolia/Fulu sync fixes), new validation-suite tests, and upcoming cross-client interop.

## Development Progress

### Hive & Build Compatibility

- **Grandine image regression**: [Kayden] Grandine flagged that their latest version wasn't being used on Hive after a Docker-tag change, which also surfaced ream image failures; fixing two issues — ream was cross-compiled against a newer glibc than the Docker container ships (so it failed to start), and the SSL root certificates were missing.
- **Multi-stage Docker build**: [Mohit] Reworked the ream Dockerfile into a multi-stage build that separates the devnet-4 and devnet-5 source images, since the old image used the devnet-4 image as the runtime base and couldn't run the devnet-5 libraries.

### Testing & Simulation

- **Long-run benchmarking**: [Derek] Benchmarked memory and CPU across devnet runs up to ~8,000 slots to characterize behavior over longer runs, and tested Shadow against ethlambda.
- **Validation-suite tests**: [Mohit] Submitted a PR adding three validation-suite test cases — future-slot horizon rejection, recovery after an invalid score set, and duplicate valid-block handling — plus libp2p-mock changes: anonymous gossipsub validation matching ream's plans, a 16 MB mock gossip transmit limit (up from libp2p's 64 KB default, which had been dropping valid devnet-5 blocks before tests received them), a configurable genesis delay, and a helper to match client-generated blocks against fork-choice state and assert rejected blocks stay out of the store. Hopes Kolby and Derek review it this week.
- **JWT test fix**: [Perfogic] Opened a PR fixing the JWT after a dependency update broke the beacon-client block-production and checkpoint-conversion test, plus a second PR for a suspected ream-client bug (Kolby reviewed, responses given); awaiting review on both.

### Data Availability

- **Parent/child DA import**: [Perfogic] Continuing DA work on the ream beacon client — handling the case where a child block arrives before its parent block's data availability is fully imported (not enough columns received) — and checking the implementation against Lighthouse; aiming to finish this week.
- **Sepolia sync & Fulu config**: [Hans] Working toward full compatibility by syncing against the Sepolia testnet and filing bugs; has a draft PR fixing configuration bugs around initializing config to accept other peers and handling the Fulu-epoch checkpoint, and is continuing to investigate the remaining sync issues.

### Interop

- **Cross-client interop**: [Shariq] After a light week, aiming next to get interop working between ream's main branch and ethlambda and zeam.
