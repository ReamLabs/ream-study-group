# Ream Meeting #80 Recap

## Overview

This week's call was a compact, roughly half-hour status sweep spanning memory pressure on long-running devnets, Shadow simulator experimentation and Hive flakiness, a set of sync and consensus correctness fixes, execution-layer integration, aggregation topology, and networking and data-layer work.

## Development Progress

### Memory & Long-Running Stability

- **Long-devnet crashes**: [Shariq] Ran a heavily-optimized 24-node devnet; ream nodes start crashing on memory around ~10,000 slots on the longer runs — not yet diagnosed.
- **20k-slot crash**: [Kayden] Looked into the memory crash seen on a ~20,000-slot devnet; no root cause pinned down yet.
- **Memory vs ethlambda**: [Derek] After ruling out cores and RAM on his own machine (and upgrading it), concluded ream simply uses more memory than ethlambda — six lean-start nodes left only ~4 GB free — and flagged it as something to investigate.

### Testing & Simulation

- **Shadow hardware requirements**: [Derek] Extensive Shadow runs pointed to one node per hardware thread as the ideal; extra nodes still run but simulation time balloons from context switching. A 24-node run across eight subnets finalized, but took ~4 hours to simulate ~3 minutes of runtime, and 32 GB wasn't enough (it leaked to swap). Suggests hosted/rented compute for larger public Shadow runs.
- **Hive flakiness**: [Sahil] All leanSpec and sync tests pass locally, yet the same suites intermittently fail on Hive with no ream change between the 13th and 14th runs — pointing at Hive caching responses rather than a client regression. Proposed updating the test driver every ~2 weeks instead of weekly, since the fixture bumps are trivial.
- **Late-joiner sync**: [Kayden] Saw the "late joiner syncs and finalizes" Hive case failing, tested locally, and the next Hive run passed. [Sahil] Shariq's PR adding the native CPU to ream's config TOML fixed that case.
- **Hive fixture pinning**: [Richard] Investigated the devnet-4 state-transition fixtures — all 45 cases pin the post slot, but only 5 pin the latest block-header state root and 25 of 45 pin justified slots that the driver response contract doesn't carry (so they're silently dropped). Working out whether this is a deliberate design choice or a gap, extending the check to fork choice and verify-signature, and planning a proposal to tighten the leanSpec generator's pinnings and widen the driver response and Hive assertions.
- **End-to-end beacon test**: [Perfogic] Wrote an end-to-end test for the beacon client's block producer and checkpoint conversions, and surfaced a mismatch between the beacon side and the consensus spec. Two nodes finalize on CI, but with four nodes two go out of sync for ~2 epochs after ~10 minutes (it works locally) — a follow-up issue will track that. Handed the test to Shariq for review and documented the findings.
- **Multi-node test init**: [Hans] Merged an end-to-end beacon-node test that adds an initializer to bypass the one-slot global beacon-network-spec init so multiple nodes can run in one process.
- **Formal verification**: [Perfogic] Contributed to two PRs on the leanSpec formal-verification work.

### Sync & Consensus Correctness

- **Sync-lag gate false trigger**: [Soham] Revisited a two-month-old sync-lag-gate PR (Kolby had asked for a rebase) and found an issue in leanSpec itself: when a node misses blocks for four slots it enters the gate and pauses validator duties, so four consecutive validators going offline can trick the whole network into thinking it's lagging and healthy nodes stop authoring. Confirmed on a local devnet; the fix is simple — a node should author a block whenever it can.
- **Grief on syncing nodes**: [Soham] A node supplying payloads to a syncing peer can grief it with malicious payloads that drive CPU to 100%; the fix is simple and in testing on a local devnet, with a PR to follow.
- **Sync stall on no common checkpoint**: [Derek] Fixed a sync stall that hit when connected peers shared no common checkpoint — filter outliers and, on a reorg, pick the highest of the cluster to sync to.
- **180-slot reorg**: [Kayden] Landed the fix for the 180-slot reorg issue raised last time; also reviewed and merged one of Soham's PRs and Shariq's follow-up optimization for building the block early in the slot.
- **Stale-attestation fork choice**: [Hans] Merged a leanSpec fork-choice fix for stale attestations, and spotted a possible optimization in verify-attestation (how it queries the block-provider table) to be handled in a separate issue.

### Execution-Layer Integration

- **reth embedded in ream**: [Sahil, Soham] First phase of embedding reth is done — a new reth crate in ream, the engine handles imported, and a basic execution payload placed into the block body; the POC compiles and builds. Remaining: more tests, docs, a working example and a demo. [Soham] The core reth and beam-chain services are done per plan; next is running it to confirm syncing/finality, shake out bugs, and check metrics.
- **Shadow signature aggregation**: [Sahil] Shadow uses fake XMSS proofs to keep aggregation cheap. Other clients' type-1 aggregation is bytes-in/bytes-out and can be faked behind a feature flag, but ream's aggregation takes single- and multi-message aggregate types, so it needs a real offline proof to stay deterministic. Proposed matching the bytes-in/bytes-out interface and shared a PR plus a video demo for review.

### Aggregation Topology

- **Multi-subnet aggregation**: [Unnawut] Aggregation time stays above four seconds, which causes finality delay, so anything beyond two subnets isn't viable right now. Paused the work pending an investigation into why even two subnets exceed four seconds.

- **Proposer data-column broadcast**: [Hans] Now working on broadcasting the proposer's data column sidecar after producing a block (PeerDAS-related).
